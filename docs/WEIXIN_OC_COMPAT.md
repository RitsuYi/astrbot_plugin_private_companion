# 个人微信实验适配包：安装与验收

版本：`7.1.6+weixin.2`（R2绑定修复），日期：2026-11-08。

这是为个人微信私聊制作的第三方实验版本，不是 menglimi 的正式发布。
基于上游提交 `05a7689aad72c0de5c84c13b934d32344f21c091`。
开发与接口测试使用 AstrBot 4.29.4，提交 `2b3aee5343b10e8148fb5935206c165ae89b4b9a`。
未登录真实微信、未用真实账号收发消息；必须在你的实例中验收。

## R2：修复首次绑定的 host_identity_invalid

R1把微信入口接通了，但漏测了“首次发送绑定命令→管理员确认→生成精确目标”的完整链路。
绑定身份校验只允许一部分ASCII标识，拒绝了真实微信发送者形如 `opaque-peer@im.wechat` 的ID，
因此消息虽然到了，绑定仍会失败；旧版还可能先写入待绑定文件、再报告身份无效。

R2允许这种有界、不带分隔符的原生ID；非法绑定先校验再落盘，错误提示保留具体字段原因。
管理面板确认后会为实际微信发送者新增精确目标，匹配时优先于旧通配符。
不会把一个新用户自动设为核心管理员，仍由现有Dashboard管理员确认。

内部 `account_id` 在此适配中继续使用平台实例ID。平台叫“爱弥斯”时，这里显示“爱弥斯”是正常的。
真实登录账号保留在AstrBot的 `weixin_oc_account_id`／微信适配器中，由原生客户端用于登录和发送。
两者用途不同；改动宿主self_id并不能单独修好拒绝微信发送者ID的校验，还会让现有路由不一致。
本版不修改宿主，不替换现有Bot／人格／记忆的归属键，与之前的记忆适配R1保持相同会话约定。

从R1升级：

1. 按下文先备份，再上传R2替换同名插件代码，确认版本为 `7.1.6+weixin.2`。
2. 在原微信私聊发送 `我会永远陪着你 爱弥斯`，回到“开始使用”刷新。
3. 已有同一条待绑定会直接复用。如果提示已有另一条待绑定，先发送 `companion_unbind` 清除候选，
   再发送上面的绑定命令。这个口令不会删除长期记忆，也不能撤销已确认的核心管理员。
4. 由Dashboard管理员确认实际私聊窗口，再检查目标对象是具体微信发送者ID，不能只有 `*`。
   原有通配模板可以继续存在；精确目标应优先匹配。
5. 若旧候选已确认且确实需要更换，在“开始使用”使用现有重置首次设置入口后再绑定，
   不要删数据库、改身份账本或手动伪造participant_id。

## 这次改了什么

- 允许 `weixin_oc` 私聊进入陪伴插件。
- 微信账号使用配置中的平台实例 ID，用户使用实际微信会话 ID；用户身份使用
  `weixin-oc-user:` 命名空间，不冒充数字 QQ 号。
- 兼容微信事件的 `event.platform` 和适配器直接保存的客户端。保留实际适配器对象、
  平台实例 ID、登录状态、客户端对象的一致性检查，不修改或猴子补丁 AstrBot。
- 接通账号发现、私聊目标、人格映射、普通回复上下文、记忆归属和原生会话发送。
- 后台发送缺少 `context_token` 时返回 `weixin_context_token_missing`。
  平台发送异常记为未确认，不作为成功回执；API 接受也不等于手机已读。
- 当前微信适配器不能发送 Record：插件普通回复的 TTS 保留文字，后台可选语音回退文字，
  必选语音明确返回 `weixin_voice_unsupported`。AstrBot 自身或其他插件的 TTS 也请关闭。

## 安装前

1. 确认 AstrBot 版本是 4.29.4。其他版本没有在本包中验证，不能只看最低版本号就认定兼容。
2. 在现有陪伴小屋里导出备份。条件允许时停机复制完整 AstrBot `data` 目录；至少保留
   插件配置、`data/plugin_data/astrbot_plugin_private_companion` 和旧插件代码。
   如果曾自定义数据位置，另备份那个目录。
3. 关闭本插件自动更新（若界面提供）；不要点“一键更新全部”覆盖这个实验版本。
4. 不要先卸载插件、不要删除插件数据，也不要重装或重新下载模型。

## 安装 ZIP

1. 打开 AstrBot WebUI → 插件 → 从本地上传，选择交付的插件 ZIP；不需要先解压。
2. AstrBot 4.29.4 能识别同名插件并替换其代码。插件 ID 仍是
   `astrbot_plugin_private_companion`，不是第二个并行插件。
3. 等待依赖检查和加载结束，必要时重启 AstrBot。
4. 确认插件版本显示 `7.1.6+weixin.2`，并能打开“陪伴小屋”。
5. 如果安装失败，保存完整错误日志。不要绕过依赖检查强行运行。

原插件的依赖较多。本包保留原有功能及依赖，没有把宿主模型或私人运行资料打进 ZIP。
加载期间可选米家等扩展缺少依赖的警告与微信连接是否成功是两回事。

## 连接个人微信

1. WebUI → 机器人 → 创建机器人 → 个人微信。
2. 给它一个固定且独立的 ID，例如 `weixin-personal`；启用，扫码确认并保存。
3. 用微信向 ClawBot 会话发一句话，先确认 AstrBot 原生聊天能正常回复。
4. 给该会话选择“爱弥斯”人格，选择已测试通过的本地或云端模型。
5. 再发送：`我会永远陪着你 爱弥斯`。
   人格名必须与 AstrBot 中现有的人格 ID 完全一致。
6. 陪伴小屋 → 开始使用／账号与会话，刷新并核对平台 `weixin_oc`、实例 ID、实际私聊用户，
   再由管理员确认绑定、保存人格映射，按引导准备并启动。
7. 微信用户 ID 可能是很长的字符串，不要改成自己的手机号、微信号或 QQ 号。
   同一个平台 ID 不要换绑另一微信账号；要换账号请用新的平台 ID 和新的绑定。

首次保持只开启文字私聊；语音、QQ空间、戳一戳和微信不存在的群聊功能不启用。
该接口是微信 ClawBot 接入，并非让程序控制任意普通微信好友窗口。

## 必做验收

- 普通聊天：发“老婆，我回来啦”，确认只收到一条正文、人格正确，日志没有
  `unsupported native event platform`、`host_client_mismatch` 或 `host_capture_failed`。
- 绑定：刷新小屋，确认出现微信窗口及正确人格；重启后仍然存在。
- 记忆：告诉它一条容易辨认的测试偏好，在小屋记忆页检查是否实际保存。
  新建会话后尝试检索。模型说“记住了”不能单独作为成功证据；记忆提取还受模型与插件配置影响。
- 主动消息：先从微信发一句话刷新会话，再在小屋给这次测试授权，手动运行一次主动联系。
  同时检查小屋回执和微信实际收到的内容；成功后再开启低频主动功能。
- 电脑关机：使用 NAS 时另验证普通聊天和插件后台任务的云端模型路由。
  本包不替你配置云端切换，单纯安装不会让离线 Ollama 自动恢复。

## 主动消息的限制

微信发送需要从用户入站消息取得的 `context_token`。凭证缺失、服务端失效或登录退出时，
不能保证主动消息送达；重新发一条微信消息可能刷新会话凭证。
没有实证支持一个固定、永久有效的时间窗口，本包不会通过定时轮询伪造续期。
缺少凭证是已知未发送；发送过程中的服务端错误按未确认处理，不自动重复发送造成刷屏。

## 测试范围和已知限制

新增 `tests/test_weixin_oc_compat.py` 使用真实 AstrBot 微信适配器／事件类，模拟 HTTP 边界，
检查身份隔离、绑定字段、账号发现、普通回复捕获、私聊回复到发送链路、记忆写入、
缺失凭证、API 报错和语音降级。具体结果见交付时的测试记录。

没有测试真实微信扫码、服务端限流、跨天会话凭证、微信图片／文件识别全链路和手机收件。
图片仍依赖模型及原插件配置；没有给纯文本 GGUF 凭空增加识图能力。
微信协议原始消息 ID 和引用消息与 QQ 不同，复杂引用／转发暂不作为首版验收目标。

上游基线有测试失败：5项旧绑定夹具断言、1项纯群聊宿主初始化测试。
已在未修改的上游提交单独复现。本包不声称全仓测试通过；QQ回归及新增微信测试另列记录。

## 回滚

暂停自动／主动功能，恢复备份的旧插件代码和相应配置；需要时从原仓库重新安装正式版。
不要删除 `plugin_data` 来回滚代码。若恢复数据快照，应同时核对配置与数据版本，
避免旧配置指向测试绑定。测试版的新微信绑定不保证被旧版读取。

## 复现接口测试

在已安装 AstrBot 4.29.4 SDK 和依赖的隔离 Python 环境，进入插件源码根目录：

```bash
python -m unittest -v tests.test_weixin_oc_compat
```

测试使用合成身份、隔离数据库和模拟 HTTP；不要改为生产数据库或真实登录令牌。
